============================================================
PROYECTO HOSPITAL DE CLINICAS
Explicación del proceso para que funcione con XAMPP
============================================================

URL PARA ABRIR EN EL NAVEGADOR:
  http://localhost/Proyecto_final_de_egreso1/html/index.html

------------------------------------------------------------
1) EL PROBLEMA DE FONDO
------------------------------------------------------------
El proyecto es una web con:
  - HTML/CSS/JS  (las páginas que se abren en el navegador)
  - PHP          (procesa formularios y conecta a la base de datos)
  - MySQL        (guarda documentos y datos)

HTML se abre solo, pero PHP NECESITA un servidor. Si abrís
cargaDoc.html con doble clic (protocolo file://), el navegador
BLOQUEA los fetch() a PHP (por seguridad no ejecuta PHP ni
deja pedir archivos por file://). Por eso hace falta Apache
(el servidor web de XAMPP).

------------------------------------------------------------
2) POR QUE DABA 404
------------------------------------------------------------
Apache sirve lo que este dentro de su raiz de documentos:
  /opt/lampp/htdocs/
y el proyecto esta en:
  /home/alan/Documentos/Proyecto_final_de_egreso1

Como el proyecto NO estaba dentro de htdocs, Apache devolvia
404 (no existe). La solucion "tipica" era 'sudo cp -r' (copiar
el proyecto cada vez), pero copiar crea una FOTO instantanea:
si editás un archivo, la copia queda desactualizada y hay que
volver a copiar.

------------------------------------------------------------
3) LA SOLUCION ELEGIDA: ENLACE + ALIAS (sin copias)
------------------------------------------------------------
En lugar de copiar, se apunta Apache al lugar real del proyecto.

a) ENLACE SIMBOLICO (symlink): "acceso directo".
   El proyecto fisico sigue en tu carpeta, pero htdocs muestra
   un portal hacia el:

   /opt/lampp/htdocs/Proyecto_final_de_egreso1
        -> /home/alan/Documentos/Proyecto_final_de_egreso1

   Comando:
     sudo ln -s /home/alan/Documentos/Proyecto_final_de_egreso1 \
                /opt/lampp/htdocs/Proyecto_final_de_egreso1

   Cualquier cambio se ve al instante en el navegador.
   Cero copias, cero sincronizaciones.

b) ALIAS en la configuracion de Apache:
   El symlink solo no basto (dio 403). La solucion robusta fue
   declarar un mapeo directo URL -> carpeta en /opt/lampp/etc/httpd.conf:

     Alias /Proyecto_final_de_egreso1 "/home/alan/Documentos/Proyecto_final_de_egreso1"

   Con el Alias, Apache sabe: "cuando piden
   /Proyecto_final_de_egreso1/... los archivos reales estan en
   /home/alan/Documentos/..." sin depender de seguir symlinks.

------------------------------------------------------------
4) ERRORES ENCONTRADOS (cadena de diagnósticos)
------------------------------------------------------------
ERROR 1: AH00037 - Symbolic link not allowed
  La config raiz de Apache tiene:
      <Directory />
          Require all denied
      </Directory>
  Significa: "todo lo que no este explicitamente permitido queda
  denegado". El symlink apunta por fuera de htdocs, sin reglas.
  Arreglo parcial: agregar un bloque de permisos:
      <Directory "/home/alan/Documentos/Proyecto_final_de_egreso1">
          Options Indexes FollowSymLinks ExecCGI Includes
          AllowOverride All
          Require all granted
      </Directory>

ERROR 2: AH00035 - search permissions are missing
  Con el Alias seguia 403. Apache no podia atravesar /home/alan:
  la carpeta personal esta en 750 (drwxr-x---) y solo permite
  entrar a su dueño y su grupo. Apache corre como usuario 'daemon'.
  Arreglo (se agrego daemon al grupo del usuario):
      sudo usermod -a -G alan daemon
  NOTA: cambiar de grupo no afecta procesos ya corriendo, por eso
  hubo que REINICIAR Apache completo. Despues respondio 200 OK.

ERROR 3: Field 'id_documento' doesn't have a default value
  La tabla Documentos tenia id_documento int NOT NULL SIN
  AUTO_INCREMENT, por lo que el INSERT fallaba.
  Arreglo:
      ALTER TABLE Documentos MODIFY id_documento INT(11) NOT NULL AUTO_INCREMENT;
  Respaldo en: sql/fix_documentos.sql

ERROR 4: Guardado del archivo (Documento/)
  - Se creo la carpeta php/Documento/ (donde PHP guarda los PDFs).
  - Permisos 777 para que Apache (usuario daemon) pueda escribir.
  - Se mejoro php/cargaDocumentos.php: ruta absoluta con __DIR__,
    crea la carpeta si falta, verifica permisos y devuelve el
    mensaje de error exacto del servidor.

------------------------------------------------------------
5) VERIFICACION FINAL (todo en vivo por HTTP)
------------------------------------------------------------
  1) index.html     -> 200 OK
  2) trazabilidad.html -> 200 OK
  3) Subida de PDF por POST al PHP -> "Registro Exitoso"
  4) Base de datos  -> fila creada (id_documento, nombre, archivo)
  5) Disco          -> PDF guardado en php/Documento/

------------------------------------------------------------
6) RESUMEN DE LO CONFIGURADO
------------------------------------------------------------
  | Componente       | Qué se configuró                          |
  |------------------|-------------------------------------------|
  | htdocs           | Enlace simbólico hacia el proyecto        |
  | httpd.conf       | Alias + bloque <Directory> con permisos   |
  | Usuario Apache   | daemon agregado al grupo alan             |
  | php/Documento    | Carpeta de subida con permisos 777        |
  | Base de datos    | id_documento con AUTO_INCREMENT           |
  | cargaDocumentos.php | Ruta absoluta y mejores mensajes     |

  Si algún día cambiás de máquina: el proyecto viaja solo (todo
  está dentro de tu carpeta). Solo hay que repetir el enlace +
  el Alias + usermod. El script configurar_htdocs.sh automatiza
  gran parte de esa configuración.
